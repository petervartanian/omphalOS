# omphalOS System Overview

Computational infrastructure for institutionalized doubt.

## What It Does

Surfaces patterns in trade data for analytical review. Forces the record to carry uncertainty, rival explanations, and falsifiers as first-class structure. Makes epistemic humility architecturally unavoidable.

## Core Components

### Objects
- **Cases**: investigative questions + scope + selected investigations
- **Runs**: portable executions → checksummed artifacts
- **Packets**: claims + mandatory doubt structure (unknowns, alternatives, falsifiers)

### Enforcement
- **Export Gate**: Rejects packets lacking unknowns/alternatives/falsifiers
- **SQL Standards**: Investigations require 60+ Canon lines, 45+ Margin lines, terminal LIMIT
- **Conformance Suite**: Gates releases (pack verification, case execution, integrity checks, export gate evaluation, polycentric verification)

### Verification
- **Python**: Reference runtime, case orchestration
- **Rust**: Cryptographic attestation, schema validation
- **Go**: Independent SQL execution, result verification

No single implementation is authoritative.

## Investigation Catalog

20,000 SQL queries detecting patterns:
- Payment fragmentation (threshold evasion)
- Entity clustering (shell networks)
- Temporal anomalies (sanctions stockpiling)
- Cross-domain procurement (proliferation activity)
- Price outliers (transfer pricing, barter)
- Network topology (transshipment routes)

Each investigation: Canon/Margin headers (epistemic safeguards), metadata (domain/intent/method), CTE-based SQL (reviewable), LIMIT clause (bounded results).

## The Canon

Every SQL investigation contains 60+ repetitions of "interpret with restraint; prefer simpler explanations; record unknowns" before the query executes.

This is not documentation. It is infrastructure exploiting cognitive psychology: repeated environmental cues durably shift judgment patterns where single warnings fail.

## Operational Context

Used by intelligence analysts, export control investigators, sanctions compliance officers, trade finance investigators in adversarial legal contexts where analytical reasoning must survive scrutiny.

Application domains: export control (EAR, ITAR), sanctions enforcement (OFAC, multilateral regimes), trade-based money laundering, supply chain risk, proliferation finance.

Three years after a case closes, the exact analytical process is reproducible bit-for-bit.

## Architecture Properties

- **Offline-first**: Operates in air-gapped environments
- **Polycentric**: Trust distributed across implementations
- **Checksummed**: Every artifact has SHA-256 hash
- **Portable**: Runs snapshot cases and packs
- **Transparent**: Human-readable SQL under version control
- **Hypothesis-generating**: Not classification, not risk scoring, not real-time monitoring

## Conformance Contract

Schemas frozen at `core/schemas/`:
- `case.json` — Case definition
- `packet.json` — Analytical product with mandatory epistemic scaffolding
- `run.json` — Portable run manifest

No release without conformance passing offline.

## The Principle

Epistemic humility is architectural, not aspirational.

The export gate does not suggest—it blocks.
The conformance suite does not recommend—it gates releases.
The Canon does not remind—it forces scrolling through 105 lines before execution.

This is computational enforcement of doubt.
